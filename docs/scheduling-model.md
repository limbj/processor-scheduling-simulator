# 시뮬레이션 모델

[프로젝트 소개](../README.md) · [사용 안내](usage.md)

## 시간과 작업량

시뮬레이션은 1초를 나타내는 tick 단위로 진행합니다. AT는 도착 시간, BT는 처리해야 할 작업량(work units)입니다. 코어의 처리 성능에 따라 같은 BT도 실제 실행 tick 수가 달라집니다.

최대 4개 코어를 사용하며 P-Core는 최대 3개, E-Core는 최대 1개입니다.

## P-Core와 E-Core

| 코어 | tick당 처리량 | 동작 가산값 | 유휴 후 시동 가산값 |
| --- | ---: | ---: | ---: |
| P-Core | 2 work units | 3.0 | 0.5 |
| E-Core | 1 work unit | 1.0 | 0.1 |

동작 중인 코어에는 매 tick 동작 가산값을 더하고, 유휴 상태에서 다시 작업을 시작하면 시동 가산값을 더합니다. 표시 값은 기존 프로젝트 정의에 따른 누적 전력 모델 값(W)입니다.

## 지표 계산

| 지표 | 계산 기준 |
| --- | --- |
| AT | 프로세스 도착 시각 |
| BT | 처음 입력한 작업량 |
| RUN | 프로세스가 실제 실행된 tick 수 |
| WT | 준비 큐에서 대기한 tick 수 |
| TT | 종료 시각 − 도착 시각 |
| NTT | TT ÷ RUN |
| 실행 시간 | 전체 시뮬레이션의 종료 tick |
| 총 전력 사용량 | 코어별 누적 전력 모델 값의 합 |

P/E-Core의 처리량이 다르므로 이 프로젝트의 NTT는 BT 대신 실제 실행 tick 수인 RUN으로 정규화합니다. 평균 WT·NTT는 정상 완료된 프로세스만 집계하며, 정상 완료가 없으면 0을 표시합니다.

## DRR 시나리오 생성

GPT 모델과 질문 복잡도로 로컬 프로세스 입력을 생성합니다. 선택 조합마다 프로세스 3개를 추가합니다.

| 질문 복잡도 | 생성 범위 |
| --- | --- |
| 낮음 | 1~5 |
| 보통 | 6~15 |
| 높음 | 16~30 |

- GPT 3.5: BT = 복잡도 × 1
- GPT 4: BT = 복잡도 × 2
- BT의 최댓값은 45이며 도착 시간은 0~15 범위에서 생성합니다.

## DRR 코어 배치

1. 남은 작업량이 1 이하이거나 복잡도가 1~5이면 E-Core를 우선 사용합니다.
2. 그 외에는 P-Core를 우선 사용합니다.
3. 선호 코어가 모두 사용 중이면 유휴 상태인 다른 종류의 코어도 사용합니다.

## DRR 시간 할당량

처음 배치할 때와 선점 후 다시 배치할 때, 남은 작업량에 따라 시간 할당량을 계산합니다.

| 남은 작업량 | 시간 할당량 |
| --- | ---: |
| 1~10 | 2 |
| 11~20 | 4 |
| 21~30 | 6 |
| 31 이상 | 8 |

## DRR 강제 종료

초기 BT가 30 이상이고 누적 처리 작업량이 30 이상이 되면 해당 tick이 끝날 때 프로세스를 강제 종료합니다. 코어의 처리량에 따라 누적 작업량이 30을 넘은 상태에서 종료될 수도 있습니다.

GUI는 강제 종료된 프로세스에 `OUT`을 붙여 표시합니다. 해당 결과는 평균 WT·NTT 계산에서 제외하고, 이미 실행한 작업은 타임라인과 전력 모델 값에 반영합니다.
